# 17 — Tech Stack & Project Structure

> **Decided 2026-10-12: Ichor runs on its own C++ engine, not Unreal.** The engine lives
> at `engine/` in this repository. Everything below is written for that decision; the
> Unreal-era version of this document is in git history and nothing in it is binding.

## The move that shapes everything

> Build **`libworldforge`** as pure C++ with **zero engine dependencies**: no engine
> headers, no engine math types. Compile it twice:
>
> - into a **CLI tool** for iteration, testing, and batch runs
> - into the **engine** for the shipped forge step

Same code, two hosts. Today only the first host is wired up: `forge-cli` and the engine's tests
include `libworldforge`, but the engine's own forge still draws a stand-in terrain
(`engine/world/forge.h`) until SEED-449 swaps in the real phases. Two-second compile cycles and image-diffable output while designing
world generation, and a single implementation at ship time. This rule predates the engine
decision and survives it untouched, which is the best argument for it.

The deciding constraint is **embeddability**, not speed: the forge runs on the player's
machine, so a separate executable plus IPC is awkward. A library solves it cleanly.

## Why a custom engine

The honest case against: Unreal ships world partition, Nanite, Lumen, Landscape, a navmesh,
an animation toolchain and an editor, and rebuilding the subset Ichor needs is months of
work before a single fight can be measured again.

The case for, which won:

- **Nothing in Ichor is authored in an editor.** The world is forged, dungeons are
  assembled from kits, assets are generated by script. The Unreal editor was the part of
  Unreal this project used least and fought most.
- **Iteration speed is the daily tax.** A two-minute compile-and-launch for every tuning
  constant, over a multi-year project, costs more than the engine does.
- **The design is unusually engine-shaped already.** Deterministic IDs, event-sourced state,
  forge-once worlds, `data/` as the single source of truth, a generator with no engine
  dependencies. Those are engine design decisions wearing a game's clothes.
- **Everything is testable.** A renderer with a null backend, a fixed-timestep simulation
  and a replayable input stream let the whole game run headless in CI. That is not
  available in Unreal without a fight.

What it costs is written down in [the engine milestones](#order-of-work) so the price is
visible, not hidden in optimism.

## Layout

```
seedforge/

  engine/               the engine. C++20, CMake, vcpkg
    core/ platform/ gfx/ sim/ anim/ audio/ script/ assets/ ui/ editor/ tools/
                        the E1 to E7 subsystems: math, rng and logging; SDL3 window and input;
                        the Vulkan renderer; ECS, Jolt and fixed-step scheduler; ozz animation;
                        miniaudio; Lua host; cooker; RmlUi screens and ImGui tools; the editor
    world/              forge validation, the engine bake (phase 12), streaming, navmesh, weather
    data/ save/ ledger/ factions/ npc/ economy/ progression/ traversal/ loop/ net/ ...
                        the game rule modules, one per system (C++ with tests, per rule 10 below)
    tests/              unit, headless, golden image, replay, fuzz (benchmarks are not set up)
  libworldforge/        pure C++, no engine. Phases 1–11, header-only
    include/worldforge/ one header per phase (tectonics … poi, subseed)
    CMakeLists.txt      INTERFACE library `worldforge`; no src/ or tests/ here, tests live in engine/tests
  forge-cli/            CLI wrapper → PNGs, manifest, batch runs
    viewer/             the map viewer: static offline HTML/JS, no Node needed
  data/                 SHARED source of truth (JSON)
    axioms/  synergies/  catalogue/  kits/  grammars/  ... (one folder per feature)
  viewer/               placeholder README only; the working viewer is forge-cli/viewer/
  game/                 Ichor itself
    stage0/             the doc 18 combat experiment, first code on the engine
  tools/                check_deps.py, check_content_layout.py (both run in ctest)
  art/                  Blender sources, generated textures and audio
  tracker/              the backlog, as JSON
```

`game/` held the Unreal project until Stage 0 ran on the engine; that tree was deleted on
2026-10-12 at the end of milestone E4 and lives on in git history. `game/stage0/` is the
experiment itself, built with the engine.

**`data/` being shared is the important bit.** Axioms are read by *both* the generator and
the game; two copies will diverge within a month.

**Content is organised by feature, not by asset type**: `data/progression/trainers.json`,
not `data/json/trainers.json`. Folders are lower snake_case and never named after an asset
type. `data/` files are snake_case `.json`; `art/` files are `T_` textures, `SM_`/`SK_`
meshes and `A_` audio in PascalCase, fonts as `Family-Style`, Blender sources and scripts
in snake_case. `tools/check_content_layout.py` enforces this in ctest; the debt it
tolerates is listed in `tools/content_layout_baseline.txt` and only shrinks.

## The stack

Every entry is a decision somebody made on purpose. Replacing one is a ticket, not a
Tuesday.

| Concern | Choice | Why |
|---|---|---|
| Language, build | **C++20**, **CMake**, **vcpkg** manifest | Modules and concepts help; the manifest is the written-down list of dependencies |
| Platform | **SDL3** | Window, input, gamepad, file dialogs, done |
| Graphics | **Vulkan** via vk-bootstrap and VMA | Best tooling for a custom renderer: validation layers, RenderDoc |
| Shaders | **HLSL** compiled with DXC to SPIR-V | One shader language if DX12 is ever added |
| Math | **GLM** | Standard, header only, no engine coupling |
| ECS | **EnTT** | Simple, fast, well understood |
| Physics | **Jolt** | Built for open worlds, deterministic, multi-threaded |
| Audio | **miniaudio** | Small, embeddable, no licence tier |
| Animation | **ozz-animation** | Skeletal sampling and blending; state machines are ours |
| Assets in | **cgltf**, **stb_image**, **meshoptimizer**, **bc7enc** (vendored, MIT) | glTF and PNG in, cooked binary out with size-capped, mip-mapped, BC7/BC5/BC4 block-compressed textures in our own bundle; KTX2 + basis_universal stay an option for E5 |
| Navigation | **Recast / Detour** | Navmesh per streaming cell, stitched at borders |
| UI | **Dear ImGui** (tools), **RmlUi** (game) | Tools first; the game UI is minimal by design |
| Scripting | **Lua** via **sol2** | Quests, dialogue and encounter scripts live in data |
| Data in | **nlohmann-json** | `data/` is JSON; the generator tools and the data loaders parse it |
| Serialisation | own reflection + binary writer | The ledger is a few hundred thousand small facts; see [14](14-save-system.md) |
| Profiling | **Tracy**, **RenderDoc** | |
| Tests | **Catch2**, **Google Benchmark**, **libFuzzer** | |

Not wired up yet: Google Benchmark (it is not in the vcpkg manifest, so the Performance row below
has no runner), and the fuzz targets are `ichor_forge_fuzz` and friends rather than a nightly job.

Not chosen, on purpose: Wwise and FMOD (licence tier, integration time, miniaudio is enough
until the music system proves otherwise), flecs (EnTT is simpler and the ECS is not where
Ichor's complexity lives), a scripting layer for gameplay *rules* (those are C++ and tested).

## Engine architecture rules

Written before the first subsystem so they cannot be retrofitted later.

1. **Core is a library; platform and game are hosts.** `engine/core` and `engine/sim`
   compile without a window, a GPU or an audio device. Tests link them directly.
2. **Every device has a null backend.** Null renderer, null audio, null input, null window.
   The headless build is the default test target, not a special mode.
3. **Fixed timestep for simulation.** Rendering interpolates. Combat frame data, physics
   and AI tick at a fixed rate, so a fight is the same fight at 30 and 144 Hz.
4. **One seeded RNG per system, passed explicitly.** Never a global random source. This
   is what makes replay and determinism tests possible.
5. **Input is a recorded stream.** The game consumes an input stream; live play and replay
   are the same code path. Every bug report is a replay file.
6. **Mutate state only through the command layer.** Doc 15's rule, now an engine rule:
   gameplay systems emit commands, the ledger records them, nothing writes state directly.
7. **Server-authoritative shape from day one.** Single-player is a one-player server, per
   [15](15-multiplayer.md#what-must-be-decided-now-regardless).
8. **Camera-relative rendering.** Floats lose precision past a few kilometres; the world
   is 4 km and the origin is wherever the camera is.
9. **Stable string and hashed IDs, never indices.** Doc 14's rule applies to every asset
   and entity, not just saved ones.
10. **No gameplay logic in Lua.** Lua composes content: which NPC says what, what a quest
    step checks. Rules (damage, stamina, stagger, standing) are C++ with unit tests.

## Languages and data

**Generator:** prototype in Python/NumPy, port phase by phase to C++ diffing debug images.
Unchanged; see [08](08-world-generation.md#prototype-first).

**Game:** C++ for anything per-frame or per-entity: the ledger, quest binding, combat, AI.
Lua for composition: dialogue, quest steps, encounter dressing, tuning tables that change
fifty times a day.

**Data:** author in **JSON**. The engine loads `data/` directly today (`DataSet::loadDirectory`),
and so does the generator. The cooker handles glTF and audio only. Cooking the JSON into a binary
format so the runtime never parses it is a goal, not built, and undecided until load time shows a
cost.

## Version control

**Git + LFS.** Everything except cooked content and `art/` is pure text. Perforce only if
LFS operations start costing minutes; do not pre-empt it solo.

Ignore from day one: `build/`, `.cache/`, `*.cooked`, cooked content directories, and any
IDE folder.

## Iteration speed: the daily tax

- The generator stays out of the engine (2 s, not 2 min)
- **Hot reload for shaders, Lua, JSON data and cooked assets.** Change a stamina constant,
  see it next frame. This is the single feature that pays for the engine.
- Unity builds and precompiled headers per module; watch header bloat
- A `--scene` flag that boots straight into a test scene with the debug HUD up

## Testing

The engine is built to be tested, and the tests are built with the engine, not after it.

| Level | What | Runs |
|---|---|---|
| **Unit** | math, serialisation round-trips, ECS queries, allocators, parsers, every gameplay rule | every push |
| **Headless** | load a scene with null backends, tick N fixed steps, assert on state | every push |
| **Replay** | recorded input stream through a scene, assert the final world state hash | every push |
| **Save/load round-trip** | mutate the ledger, save, load, compare. **The one game-side test worth insisting on.** The restored state is bit-exact; a physics run *continued* from a snapshot tracks the original closely rather than bit for bit, because Jolt's character keeps transient contact state no snapshot carries | every push |
| **Determinism** | same seed twice, byte-identical forge output and byte-identical replay. Pose sampling feeds root motion into the hashed state; ozz's SSE path is deterministic per machine but its reciprocal square root estimates are not promised identical across CPU vendors, so cross-machine replay of animated characters is pinned by the golden tests rather than assumed | every push |
| **Golden image** | render reference scenes offscreen, diff against stored images with tolerance | nightly, main |
| **Performance** | reference walk through the densest cell; fail on frame time or hitch budget | nightly, main |
| **Fuzz** | asset cooker inputs, save file loader, network packets later | nightly |
| **Sanitizers** | AddressSanitizer and UndefinedBehaviorSanitizer on one CI job | every push |

The high-value one, specific to this project:

> **A batch seed harness.** Run 1,000 seeds through phases 0–11 and report
> [validation-gate](08-world-generation.md#validation-gates) failures by cause.

Build it as soon as the validation gates exist.

**Streaming is tested headless.** A scripted player crosses every cell boundary in a
forged world with null backends; the test asserts which cells are resident and that
nothing leaks. This is the single most valuable test an open world can have.

## Dependencies are a written-down list

The vcpkg manifest is the list. Every entry carries a one-line *why* in the stack table
above, and `tools/check_deps.py` fails CI when the manifest and the table disagree. A new
dependency is not necessarily wrong; one that arrived without anyone recording why is.

## The map viewer

The CLI emits a manifest plus phase PNGs, and a small **local web viewer** renders them with
toggleable overlays. It is built: `forge-cli/viewer/` is a static, offline page (open
`index.html`, no server, no Node needed to use it; `check.js` is a Node smoke test). The top-level
`viewer/` folder is a placeholder that points there. Building it in a browser keeps it fast to
change, and it stays useful after the engine has its own editor.

## Order of work

The engine milestones come first because [Stage 0](18-vertical-slice.md) now runs on the
engine. Each is gated on its tests, not on a feeling.

| # | Milestone | Done when |
|---|---|---|
| **E1** | **Scaffold.** CMake, vcpkg, SDL3 window, Vulkan triangle, ImGui, Tracy, Catch2, null backends, headless test target, CI with sanitizers | CI green on a push; the headless test boots and ticks an empty scene |
| **E2** | **Render a scene.** Asset cooker, glTF in, PBR materials, cascaded shadows, camera-relative transforms, debug draw | golden image test of a reference scene passes |
| **E3** | **World model.** EnTT scene, reflection, binary serialisation, scene files, hot reload, command layer, seeded RNG | save/load round-trip and replay tests pass |
| **E4** | **Bodies.** Jolt, character controller, fixed timestep, ozz skeletal animation, montages with frame-accurate wind-up and recovery, root motion, audio playback | **Stage 0 runs here.** The grey-box arena from doc 18 is rebuilt and the gate is run |
| **E5** | **Terrain and streaming.** Heightmap clipmaps from the forged `heightmap.r16`, splat materials, cell streaming, LOD and impostors, Recast navmesh per cell | headless streaming test passes on a forged 4 km world |
| **E6** | **Content layer.** Lua host, RPG data layer from `data/`, RmlUi screens, the ledger as the save file | the 500 m slice from doc 18 is playable |
| **E7** | **Atmosphere.** Time of day, sky, fog, weather, vegetation instancing, reverb stamps, then the editor | doc 16's unification stack is implemented |

Status: E1 through E6 are merged apart from the pieces listed here, and E7 is mostly done.
The Stage 0 gate has not been run by a human yet. Still open:

- E6: RmlUi screens in the window (no font chosen, so no text), and the doc 18 500 m slice itself.
- E5: the terrain is still the stand-in noise (see the layout note above); impostors are not built.
- E7: volumetric fog, vegetation impostors, and editor tools for kits and dungeons.
- The window paths (`--editor`, time of day and weather in the app, the UI renderer) are covered by offscreen golden images and headless tests but have never been run in a real window.

Engine-independent work that already landed: libworldforge phases 1 to 11 in C++ (the NumPy
prototype step was skipped for them), the web viewer, and the batch seed harness
(`ichor_forge_cli --validate`, plus `engine/tools/seed_harness`). Still open on that side: phase 0
(axioms into a `WorldConfig`) and wiring the real phases into the engine's forge (SEED-449), then the
phase 12 bake in doc 08.

E1 through E4 is a general 3D engine. E5 through E7 is where the open-world cost lives and
each is a multi-month effort for one person. The Stage 0 gate sits at the end of E4
deliberately: it is the earliest point at which a fight can be measured honestly.
